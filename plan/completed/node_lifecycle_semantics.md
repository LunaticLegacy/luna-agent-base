# Agent / Tool 节点生命周期语义方案

## 1. 目标

动态 agent swarm 需要支持“自进化”，因此新增节点不应只有一种一次性语义。

本方案定义两类新增节点生命周期：

- **持久节点**：进入 swarm 的长期结构，直到被显式编辑删除、禁用、替换或回滚
- **临时节点**：只服务于当前 run 或当前局部任务，用完即弃

该语义同时适用于：

- agent 节点
- tool 节点

---

## 2. 核心结论

### 2.1 持久节点

持久节点代表 swarm 已经吸收并沉淀下来的能力。

其语义是：

- 一旦加入图中，就长期存在
- 只有在显式编辑时才移除
- 可以被后续 run、后续任务继续复用
- 适合经过验证、稳定、有复用价值的 agent / tool / router / reviewer / coordinator

### 2.2 临时节点

临时节点代表一次性实验、补偿或局部派生能力。

其语义是：

- 只在当前 run、当前任务窗口内存在
- 完成后可以自动清理
- 不应长期污染主图
- 适合研究型 agent、临时工具封装、短生命周期补偿节点

---

## 3. 设计原则

### 3.1 支持自进化

swarm 允许持续吸收新能力，因此持久节点是必要的。

如果某个新增节点反复证明有效，就应允许它保留在 swarm 中，成为长期结构的一部分。

### 3.2 支持治理

swarm 不能无限增长，否则会出现：

- 节点膨胀
- 图结构过密
- 路由复杂度上升
- 无效节点污染调度

因此，持久增长必须配套：

- 禁用
- 归档
- 替换
- 回滚
- 退役

### 3.3 默认安全

默认应偏向临时语义，除非明确声明为持久节点。

这样可以降低实验性节点误入主图的风险。

---

## 4. 建议的生命周期模型

建议把节点生命周期抽象为以下状态：

| 状态 | 含义 |
|------|------|
| `transient` | 临时节点，用完即弃 |
| `persistent` | 持久节点，长期保留 |
| `candidate` | 候选节点，试运行后决定是否升级 |
| `disabled` | 仍在图中，但不参与调度 |
| `archived` | 逻辑保留，主图不再直接调度 |

### 4.1 推荐默认值

- 新增 agent 节点默认：`transient`
- 新增 tool 节点默认：`transient`
- 只有明确声明或经评估通过，才提升为 `persistent`

---

## 5. 节点类型语义

### 5.1 Agent 节点

agent 节点的持久化，表示一个可长期调度的执行角色。

适合持久化的典型例子：

- planner
- reviewer
- coordinator
- stable researcher
- domain specialist

临时 agent 节点更适合：

- 一次性研究
- 局部补偿
- 短期实验
- 临时分支执行

### 5.2 Tool 节点

tool 节点也应支持同样的生命周期。

tool 节点的持久化，表示一个可复用的操作能力。

适合持久化的典型例子：

- file writer
- graph editor
- search
- validation
- common formatter

临时 tool 节点更适合：

- 临时 API 包装
- 一次性格式转换
- 局部适配器
- 任务专用的 glue tool

---

## 6. 创建与清理语义

### 6.1 创建

新增节点时必须允许显式声明：

- `kind = agent | tool`
- `persistence = transient | persistent`
- `lifetime_policy = run | session | swarm | manual`

### 6.2 清理

临时节点完成后可以自动清理。

持久节点不应自动清理，只能通过显式图编辑处理：

- 删除
- 禁用
- 归档
- 替换

### 6.3 推荐的清理顺序

对于不再有价值的持久节点，建议按以下顺序处理：

1. `disabled`
2. `archived`
3. `removed`

这样能保留历史可追溯性，也方便回滚。

---

## 7. 升级规则

临时节点可通过运行表现升级为持久节点。

建议的升级依据包括：

- 成功率高
- 复用频次高
- 稳定解决实际问题
- 未引入明显维护负担

建议的降级依据包括：

- 长期不用
- 错误率高
- 维护成本高
- 与当前 swarm 目标不再匹配

---

## 8. 产品语义建议

可以把对外语义定义为：

- **临时节点**：用完即弃
- **持久节点**：可长期留存，直到被显式删除
- **图可自进化**：通过持续增加和筛选节点形成能力沉淀
- **图可治理**：通过禁用、归档和退役避免无限膨胀

---

## 9. 结论

这个语义是合理的，而且更适合动态 swarm。

它允许 swarm 持续生长，同时避免所有新增节点都永久留在图中导致结构失控。

最合适的实现方向是：

- 默认临时
- 显式持久
- 候选升级
- 退役治理
- agent 和 tool 统一支持
